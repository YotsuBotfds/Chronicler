# Inactive baseline admission interfaces

The new detached reader launches no world, build, network request, source
import or Arrow/checkpoint decoder. The completed 27f reader stays unchanged.
Its exact completed `comparison.json` SHA-256
`6343e81b4332786353c4bf83ed0c50e30db84ca10c8a428112efa5da7ba61889`
seals all eleven light-member hashes for every original historical role.

The old full run now passed original strict gates/comparisons and publication
qualification. Kin causal requirements still fail. Artifact transport was
repaired by dropping automatic forwarded Host; this reader accepts staged
ZIPs and never handles credentials, redirects or network headers.

| Interface | Contract |
| --- | --- |
| `FilePin` / `ArchivePin` | Immutable expected sizes/hashes, historical role, ID and original expiry. |
| `Budget` | Distinct 900 process-CPU/1,800 monotonic-wall seconds; checks surround reads, serialization and receipt fsync. |
| `validate_origin` / `validate_publication` | Exact old source/run/attempt/control/candidate role/native and original archive publication; reject expired/substituted evidence. |
| `build_expected_members` | Raw inventory plus excluded root result/provenance/inventory and eleven exact light copies; reject shadows/unsafe names. |

| `audit_archive` | Bounded whole-ZIP digest, stable descriptor/path identity and streamed SHA/CRC for every exact member; no extraction. |
| `prepare_baseline_plan` | Bind exact original completed reader output and all original light bytes before generating immutable expectations. |
| `audit_baseline` | Check aggregate compressed storage/publication first; sequentially hash both archives and emit an informational pending-job receipt. |
| `validate_build_bridge` | Future fully recorded common build of D028/503 may close old unknown flags only if rebuilt D028 native equals original06db exactly. Otherwise require fresh baseline worlds. |

Exact inputs: 2,126,779,694 compressed bytes combined; template55,432 file
payloads/4,256,211,501 uncompressed bytes; procedural20,332/4,896,245,631.
Pre-register 100,000 entries per ZIP, 64 MiB central directory, 6 GiB payload
per ZIP/10 GiB aggregate, 1 MiB buffers, 12 GiB disk/2 GiB RAM admission and
3 GiB/1 GiB running floor. Directory entries must name required prefixes;
duplicate, missing, extra, encrypted, symlink/special and traversing entries fail.

Auditor clocks cover local plan/archive reads, decompression, stability
rechecks, receipt encoding/hashing/fsync and final reporting. Upstream staged
transport and downstream GitHub artifact publication retain separate bounded
timing/provenance. This is not an end-to-end transfer time claim.

A local receipt is always `audit_complete_pending_job`, never a world grant.
Consumers additionally require its exact digest, the reviewed control and a
completed successful producer job. A late clock failure cannot be admitted
from a positive-looking file. Candidate admission additionally requires the
separately reviewed build/checkpoint/determinism proof pins. No active workflow
or candidate launcher is added.

Recorded old tools are rustc/cargo1.99.1, LLVM23.1.1, maturin1.15.0 and
uv0.13.6. Effective Rust flags, target overrides and linker identity remain
unknown. A future remote bridge builds both sources in one fully recorded
context: exact old binary reproduction permits reuse; different bytes refuse
reuse and require fresh baseline worlds. No build is launched here.

Pure fixture ZIPs use tiny byte strings and fake clocks. They cover complete
archives and wrong role/native/run/expiry, incomplete/unsafe/aliased members,
storage/index/stream bounds, mutation, late finalization and unknown build pins.

The resource probe currently combines host `MemAvailable` with memory metadata
at the mounted cgroup root. It does not resolve tighter descendants or hidden
ancestor limits. Before any audit job is activated, deployment must establish
that this is the process's effective memory boundary, or supply a reviewed
hierarchy-aware probe. The current pure checks do not qualify effective RAM
admission on a GitHub runner. No active job is supplied by this implementation.

Independent root review additionally found that absent producer IDs could
compare equal as `None == None`. Audit creation and completion admission now
require a lowercase 40-hex control and positive integer run/job IDs, excluding
booleans and numeric lookalikes. Empty directory entries are accepted only as
zero-size stored streams with zero CRC, and their local headers are read too.
These corrections change no scientific evidence, comparator or candidate gate.

Initial implementation qualification: **51 guarded pure cases passed**. The
guard records no native import/attempt, no blocked IO and zero runtime factory
calls. Coverage includes descriptor-relative no-follow/nonblocking FIFO-swap
rejection, finite light-directory traversal, refusal of fabricated plans,
original versus normalized ZIP names, malformed ZIP64/index allocation guards,
CRC/size/hash EOF checks, archive mutation and late parse/decompression/fsync.
Prepared immutable plans retain their original budget object, so auditing
cannot reset the metadata-stage clock. Pending receipts additionally need a
completed successful producer and exact externally bound digest.

No real historical raw archive, production plan, native build or world was
audited/executed. Actual old archive format/completeness and real memory/time
costs remain unqualified until a separately reviewed remote admission job.
The original reader/comparator, D028/503 producers, held native correction and
active workflows are unchanged. All candidate-world proof pins remain null.
