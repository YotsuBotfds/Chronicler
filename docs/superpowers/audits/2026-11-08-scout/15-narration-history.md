**Findings**
1. [high] bug — Provenance is read by simulation decisions, always on, and not mode-gated. `scholarship.py:391` (`_newly_occupied`) gates a strike; `scholarship.py:398-407` (`_sack_cause`) gates `_founding_ready` (line 768) and `_strike_sack` (line 415). `cities._lord_change`, `diplomacy._aid_convoys`, `epidemiology._reports`, `nomads._herds` also read it. `tests/test_provenance_decision_guard.py` (KNOWN_DECISION_READS, ~lines 150-190) records 7 grandfathered "decision" breaches, four on the default path. This contradicts the stated contract that provenance only records why. Action: owner decision; put each read behind a switch or replace it with a non-provenance state flag, then remove the guard entries.
2. [high] fragile — The guard only covers direct reads. `history_index` (`history_index.py:174-191`, `schism_fired`, `hegemony_fired`, `enlightenment_fired`) is read by about 12 simulation modules and is not in the guard's scope. Unverified whether those reads are decisions; check before relying on the guard.
3. [med] test-gap — The attribution "coupling to health" was not found. D2 records are write-only: every writer is a `note_*` call (`war/armies.py:325,361,453`, `war/occupation.py:64,90,224`, `cities.py:640,712`, `action_engine.py:657`, `infrastructure_condition.py:530`) and no code reads `livelihoods.attribution_records` except the viewer (`viewer/src/lib/attributionRecords.ts`) and tests. The only health-adjacent hit is `public_health.py:425`, which concerns X1 motive attribution, not D2. The last lead's coupling may live on a branch not in this checkout (unverified).
4. [low] perf — Callers build arguments before the inactive check: `war/armies.py:453-454` builds the roster list even when records are off; the inner call then returns. `armies.py:358` and `armies.py:452` are gated only by `world.livelihoods is not None`, not by `attribution_records_active`.
5. [med] fragile — LLM calls have no timeout. `llm.py:101` (OpenAI client), `llm.py:146` (Anthropic), `llm.py:244` (Gemini) use SDK defaults. Custom retry `llm.py:60-69` stacks on the SDK's own retries (SDK default retry counts unverified here).
6. [med] bug — `LocalClient.complete` (`llm.py:103-115`) has no retry, while the API clients do, so local and API failure behaviour differ. The `_TRANSIENT_ERROR_MARKERS` text match (`llm.py:19-30`) is a heuristic.
7. [med] fragile — Truncation is not detected. `_extract_anthropic_text` (`llm.py:72-80`) ignores `stop_reason`; `GeminiClient.complete` (`llm.py:278`) ignores `finish_reason`. Truncated chronicles pass as success.
8. [med] fragile — Batch polling has no deadline: `llm.py:201-208` loops until a terminal status. Expired or canceled batches return all `None` (`llm.py:211-213`), which narrative falls back to mechanical text per moment, so the failure is silent.
9. [med] gap — No budget enforcement. Only token and call counters exist (`llm.py:149-151`, `247-249`); they are printed at `main.py:2420-2423`. Narration can exceed any spend limit. Failures fall back silently (`narrative.py:1215-1216`, `1737-1742`).
10. [low] unverified — Model ids: defaults `claude-sonnet-4-6` (`llm.py:146`, `304`), `gemini-2.5-pro` (`llm.py:244`, `310`), and an empty local model. I did not check these against the current catalog (the claude-api skill was not consulted under this brief). Gemini sleeps 12 s after every call past the first (`llm.py:250`, `254-255`), a wall-clock cost for long runs.
11. [dead-code] Test-only narrative helpers, verified by grep over `src/` and `scripts/`: `build_before_summary` (`narrative.py:572`), `build_after_summary` (`654`), `build_chronicle_prompt` (`840`), `thread_domains` (`828`; no references outside the file). `render_because` (`968`) is referenced only by `tests/test_causal_provenance.py`. `build_before/after_summary` are imported by `tests/test_batch_narration.py:8`. Unverified: whether `render_because` is reached via the docstring of `render_chain_line` only.
12. [duplication] Circular lazy imports between narration and historiography: `narration_provenance.py:494,503` import `historiography.short_name` and `faith_display`; `historiography.py:575` imports `curator.event_label`; `narration_inputs.py:73` and `history_forensics.py:20` both import `historiography.AccountIndex`. Action: extract the shared label helpers to a small module.
13. [complexity] `narrative.py` (1773 lines) and `historiography.py` (2238 lines) are the largest files; both mix prompt building, mechanical rendering and state. Overlap between `narrative.py` `build_agent_context_*` and `narration_context.py` prompt rendering was inferred from names, not diffed.
14. [memory] Attribution state is bounded (`MAX_LOG`, `MAX_IDENTITY_LOG`, `MAX_ENTRIES` = 64/64/256, `attribution_records_state.py:90-93`), but `state.civs` (`attribution_records.py:759`) is appended without a cap. Provenance `keys` and `exciters` are keyed by name pairs and grow with distinct names (`provenance.py:146`, `597`). `events.causes` lists grow via `cite` (`provenance.py:118-127`). Unverified: serialized size in long runs (no runs allowed).
15. [sim-depth/quality] Chronicle selection: `curate(budget=50)` (`curator.py:944-950`) filters with `_chronicle_worthy` (`historiography.py:991-999`) against the fixed `ROUTINE` set (`historiography.py:231`). `find_boring_civs` (`interestingness.py:30`) only reports; it does not feed selection. `score_run` weights are hard-coded (`interestingness.py:8-16`). Repetition in chronicles is plausible from this design but unverified without runs.

**Simulation depth**
- Replace the grandfathered provenance decision reads with explicit, switch-gated state so that causal reasoning can become an actual input without implicit coupling.
- Give the attribution record a real consumer behind its own switch (the D1 grievance path the module comment describes), instead of a write-only log.
- Use `stop_reason` and `finish_reason` to request continuations, and vary narration across moments by giving curation a diversity term tied to repeated event types.
- Feed `interestingness` weights into `curate` selection, not only a run-level report.

**Confidence** — Verified by grep and reading: the D2 write-only property, the 7 provenance decision reads, the LLM client code, dead-helper references and the caps. Inferred: duplication overlap between the narration modules, chronicle repetitiveness and the history_index decision status. Not checked: SDK retry defaults, model catalog, run-time memory and serialized size.
