## 18 Persistence, bundles, checkpoints, live server, interactive

**Map**
- Bundles: `bundle.py` (assemble and write `chronicle_bundle.json`, Arrow sidecar), `bundle_codec.py` (version 6 `history_delta` encode/decode, `load_bundle`, gzip `archive_bundle`), `snapshot_pruning.py` (version 5 dead-civ pruning, `restore_bundle`).
- Atomic IO: `artifact_io.py` (strict JSON, temp+fsync+`os.replace`+dir fsync).
- Exact checkpoints: `run_checkpoint.py` (pickle plus per-simulator Rust state, zlib sections, SHA-256, header identity), `checkpoint_replay.py` (opt-in off-mode continuation check, used by scripts and tests).
- Live server: `live.py` (asyncio `websockets` server on a daemon thread, three queues to the simulation thread, lobby, batch worker, what-if), `live_checkpoints.py` (`LiveView` reconnect state, client checkpoint requests, `PauseInterventions`).
- `validation_io.py` (3,063 lines) is the batch loader and oracle host; it is not an IO module (see Findings 9 and 12).
- `artifacts.py` is gameplay artifacts (relics, GP items, conquest). It has no file IO; its name collides with the artifact IO modules.
- Scripts: `scripts/bundle_v6.py` (convert, decode, compare), `scripts/prune_dead_civ_snapshots.py` (v4 to v5), `scripts/verify_snapshot_session.py` (default-off admission comparison). All three are documented in `scripts/README.md`.

**Findings**
1. [high] bug: live `set` accepts `Infinity`. Python `json.loads` accepts the literal (checked: `{"value":Infinity}` gives `inf`). `live.py` `live_pause` calls `int(value)` and catches only `TypeError, ValueError` (around line 1050, the `set` branch). `int(inf)` raises `OverflowError`, which escapes. `main.py:1282` calls `on_pause` with no try, so the simulation thread dies. Whether the outer CLI catches it is unverified. Action: catch `OverflowError` or check `math.isfinite`, and add a test.
2. [med] fragile: a failed live server start is silent. `live.py:480-485` `start()` does `ready.wait(timeout=5)` and ignores the result. A bind error (port in use) kills `_run_loop` in its thread, and `run_live` (about line 1546) still prints "Lobby ready". Action: have `start()` return or raise the stored exception.
3. [med] perf: blocking work on the event loop. In `_serve`, `narrate_range` runs `copy.deepcopy(self._init_data)` (the whole history) before `to_thread`. `batch_load_bundle` and `batch_load_report` do a synchronous `read_text`, `json.loads` and pydantic revalidation (`_validate_legacy_live_bundle`, up to about 18 MB). The drain loop holds `client_lock` across `await client_ws.send`, so a slow client stalls both. Action: move those to a thread, and deep-copy only the requested turn range.
4. [med] memory and checkpoint growth. Reconnect state is kept twice: `LiveServer._init_data` (`apply_turn_message` appends per turn, `live.py` `_record_snapshot`) and `LiveView.turns` (`live_checkpoints.py:71,78`). Every connect re-parses `init` and replays all turns (`live_checkpoints.py:95-110`). `LiveView.record` pickles the whole `turns` list into each checkpoint's `live` entry, so checkpoint size grows linearly with run length. Magnitude unverified. Action: keep one store and send a bounded replay or a snapshot of the pruned history.
5. [med] security: client-chosen scenario path. `live.py:1308` (`Path("scenarios") / params["scenario"]`) and `live.py:1496` (`_record_live_world_args`) join a client string with no `resolve`/`is_relative_to` check. The batch path (`live.py:577`) passes `scenario` through the same way. `batch_load_bundle` does this check correctly, so this is inconsistent. Impact is limited by the session token and by `yaml.safe_load`, but any `*.yaml` on disk can be read. Action: apply the same output/scenarios guard.
6. [med] three bundle readers with different strictness. `validation_io.py:386-398` `_load_bundle` (read_text plus `json.loads`, strict only with a manifest, wraps every error in `RuntimeError`, no gzip). `live.py` `batch_load_bundle` (`json.loads` plus `_validate_legacy_live_bundle`, no gzip). `bundle_codec.load_bundle` (gzip-aware, no duplicate-key check). Action: one reader with a `strict` flag. Keep duplicate-key rejection for manifest batches.
7. [med] perf and memory: whole-bundle copies. `bundle_codec.decode_history` returns `json.loads(_dumps(shared))`, a full second copy of history, just to un-share dicts. `dumps_bundle` builds the entire JSON string in memory. `archive_bundle` does `source.read_bytes()` plus `json.loads` of the whole file. `validation_io.py:401-408` says a 500-turn bundle is about 18 MB. Snapshot growth per turn is damped by deltas, but each snapshot's pairwise tables are still O(civs²). Action: stream the encoder to a file, and drop the copy in `decode_history` (or document why sharing is unsafe).
8. [med] atomicity is inconsistent across writers. `artifact_io._atomic_write` is correct: O_EXCL temp, fsync, replace, dir fsync. But `historiography.py:490-496` writes a fixed `path.with_name(name + ".tmp")`, with no fsync and no uniqueness. `experiment_sessions.py:1434` has its own `_fsync_directory` that does not tolerate unsupported errnos. `bundle_codec.archive_bundle` (lines 404-444) hand-rolls temp plus hard link. Action: use `artifact_io` everywhere; document why `archive_bundle` needs its link semantics.
9. [med] `validation_io.py` is 3,063 lines because it still holds the oracles that the split did not move. It contains loaders (lines 331-1148), the needs, cohort, community and determinism oracles (about 1149-2800), and the CLI (2967-3063). It re-exports everything from `validation_common/artifacts/trajectories/regression` through a long `__all__` (line 3063). The 38-line `validation_oracles.py` is a second re-export shim. Tests patch names such as `chronicler.validation_io._read_arrow_columns` (module docstring, lines 1-14), so moving code needs patch-target updates.
10. [med] resume-exactness risks, unverified in depth. `run_checkpoint._compare_identity` covers source digest, native bytes, layouts, interpreter, packages and thread env. It does not compare the header's `flags`, which the loader never checks against the rebuilt world. `_markers` and `_rebind_markers` (`run_checkpoint.py:~365,~713`) re-bind a `id(sim)` marker, which only works because the loader recreates the same pool. `_upgrade_faiths` (`run_checkpoint.py:~722`) rewrites history on load for legacy checkpoints, and that is not flagged as non-exact unless `allow_mismatch` is used. `write_checkpoint` refuses pending storage, academy and teaching work, which is good.
11. [low] pickle trust boundary. `run_checkpoint._Unpickler.find_class` (line ~333) accepts any `chronicler.*` class. The SHA-256 detects corruption, not tampering. The docstring calls checkpoints "trusted local files", which is a stated contract, so this is a hardening item rather than a bug. Action: an explicit class allowlist.
12. [low] naming and dead-ish code. `bundle.py:44` `LEGACY_BUNDLE_VERSION = BUNDLE_VERSION` is the current version, not a legacy one. `bundle.py` has its own `HAS_ARROW` probe, duplicating `validation_io._has_pyarrow`.
13. Interactive: `interactive.py` (339 lines) and `checkpoint_replay.py` (368 lines) were not read in depth. `interactive.py` shares `PauseInterventions`. Unverified beyond that.

Clean results: the live server binds to `localhost` only (`live.py:937`), uses `hmac.compare_digest` on the token and checks Origin in `handshake_error`. Report and bundle loads resolve paths and check `is_relative_to("output")`. `checkpoint_reply` takes no client path. Incoming messages are capped at 10 MB.

**Simulation depth**
- Checkpoints and bundles already hold the full pending-signal and native state. The exact-resume contract could extend to a what-if branch that replays from a stored checkpoint, which `live_checkpoints` and `what_if` only partly do.
- Interventions are recorded as `interventions` in the run config (`live_checkpoints.py:174-181`). Richer intervention types (policy schedules, scripted shocks) would plug into the same record without a format change.
- The pruned history (`snapshot_pruning.py`) drops pair tables of dead civs, which cannot be restored. Retaining a compact per-civ death record would make dead-civ analysis exact.

**Confidence**
Verified by reading the files and by grep across `src/`, `tests/`, `scripts/` and `viewer/`. Verified by running the stdlib: `json.loads` accepts `Infinity`. Not verified: whether the outer CLI catches `OverflowError` (finding 1), checkpoint and reconnect sizes (finding 4), `interactive.py` and `checkpoint_replay.py` internals, and the compatibility consequences of the pickled `live` record beyond the code comments. No simulation, tests or native builds were run.
