**Findings**
1. [high] docs — The "200-seed before/after gate" is the `full` profile of `m53b_run_validation.py` (200 seeds x 500 turns, seeds 42-241, `scripts/m53b_run_validation.py:101-102`, `validation_gate.py:24`). Last documented runs: template 46 to 62 minutes, procedural 100 x 300 32 to 45 minutes, in `docs/integration/procedural-gates.md:722-850`. Those runs predate the connected-world merges; I could not confirm a run on `c3d752fa`, and `phase-6-progress.md:2422` says the full gate was not run for a recent branch. Not run by me (no simulation allowed).
2. [high] test-gap — Runnability today: the workflow, `m53b_run_validation.py` and the `chronicler.validate` path all exist. The CI job needs Python 3.13, a Rust toolchain and a maturin build of the native wheel. Running it needs about 1 hour of 4-core time plus roughly 2.5 GB validation memory and about 5 GB batch disk (procedural). `validation-gate.yml` needs `--baseline-report` for a before/after comparison; nothing in the workflow fetches a baseline, so the "before" must be supplied by hand.
3. [high] complexity — Five or more overlapping ways to run and compare batches: `m53b_run_validation.py` (profiles), `run_oracle_gate.py` (M28 hybrid vs aggregate, `--parallel` default 28 on a 4-core host), `m58b_convergence_gate.py` (M58b, default `--parallel 24`), `screen_runner.py` (generic held screens) plus three program-specific copies of its run/report/check (`productive_recovery_screens.py`, `livelihoods_screens.py`, `connected_world_screens.py`), and `run_expansion_experiment.py` / `expansion_experiment.py` / `compare_experiment_sessions.py`. Consolidation plan: one batch runner (m53b), one screen runner (`screen_runner.py`), one comparator (`validation_compare.py`), with the frozen preregistration scripts kept as evidence and not deleted.
4. [high] bug/stats — Seed registry is not enforced on the gate. `validation_*.py` never reads `scripts/seed_registry.json` (rg for registry and holdout returns no hits in those modules). Gate range 42-241 is labelled `restricted_gate` (`seed_registry.json`, entry `gate200-t`), yet registry entries with status `run` reuse it for development and "confirmatory" work: `gate-subsets-dev-t` [42-121, 62-81, 142-161], `credit-t` [42-81], `rs-dev-t` and `pr-dev-t` include 42, `shortfall-scaffold-t` [42]. Repeated gate runs on one fixed seed range are a repeated-look problem with no alpha spending.
5. [high] stats — No multiple-comparison correction anywhere. rg for bonferroni, holm, benjamini and fdr in `src/chronicler/validation_*.py`, `expansion_*.py` and `batch*.py` returns nothing. The needs oracle tests 5 pairings (`validation_io.py:170-176`), several snapshot turns and 8 method versions (`NEEDS_ORACLE_METHOD_VERSION = 8`, `validation_io.py:156`), against a fixed 0.95 confidence bound and 0.60 seed fraction. Method 4 to 5 was a `rebaseline_required` change (`phase-6-progress.md` near line 905).
6. [med] bug/stats — Method 1 selects the best (snapshot, pairing) candidate per seed (`run_needs_oracle_best_of`, `validation_io.py:2398-2440`). Choosing a maximum over candidates before testing is selection bias. It is kept only for re-scoring old batches, but it is still exported.
7. [med] stats — `_cohen_d` (`validation_io.py:1132`) is applied to count distributions for `effect_size` (lines 1463, 1647). Cohen's d assumes roughly normal continuous data and is not meaningful for these rates. Unverified whether any PASS criterion uses it.
8. [med] dead-code — `run_needs_oracle_best_of` has no production caller. rg shows only `tests/test_validate.py` (four tests), the re-export in `validation_oracles.py:19`, and the export-surface golden `tests/fixtures/validation_parity/goldens.json:5633-5978`.
9. [med] docs/analytics — `analytics.py` has no extractor for connected-world systems. rg for livelihood, watershed, infrastructure, institution, food shortfall, attribution, connected returns zero hits. The modules that write those systems (`watershed.py`, `war_consequences.py`, `institutions.py`, `infrastructure_condition.py`, `workshops.py` and others) have no report section. Generic `trade`/`epidemic` hits are only `trade_routes` (lines 265-297) and the epidemiology hook (lines 1396-1400).
10. [low] docs — `generate_report` hard-codes `"version": "post-M18"` (`analytics.py`, metadata block of `generate_report`).
11. [low] docs — `seed_registry.json` `unresolved` note says `scripts/m58b_convergence_gate.py` "is gone". The file exists (540 lines) and `tests/test_m58b_gate.py` imports it. The note is stale.
12. [low] fragile — `validation_oracles.py` is a re-export shim. Tests patch helpers in `validation_io`, and `tests/fixtures/performance/corrected_*.json` pins its hash (line 70). Any move breaks those pins.
13. [low] test-gap — Good practice to keep: `validation_ablation.py` uses a seed-clustered standard error with Student t (lines 12, 239-283), which respects the fact that forks of one seed are correlated. The exact one-sided sign test (`validation_io.py:1859`) is also sound.
