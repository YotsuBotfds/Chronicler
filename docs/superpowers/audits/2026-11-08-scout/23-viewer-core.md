## 23 Viewer data layer and app shell (viewer-core)

**Map**
- `viewer/src/App.tsx` (221 lines) wires three hooks: `useBundle` (uploaded file), `useLiveConnection` (WebSocket, 1 `any`), `useTimeline`. It renders `AppShell` statically; heavy panels load lazily through `components/phase75/lazyPanels.ts`.
- Upload pipeline: `lib/bundleFile.ts` (decode, gzip, checkpoint header, JSON, validation) → `lib/bundleLoader.ts` (classification, diagnostics) → `lib/bundleCodec.ts` (v6 history deltas) → `lib/bundleValidation.ts`. Large files (≥1 MiB, or `.gz`) go to `lib/bundleDecode.worker.ts` via `lib/bundleDecode.ts`, which streams 25-snapshot history slices and 2000-event timeline slices.
- `lib/bundleIndex.ts`: WeakMap indexes keyed by array identity; built lazily per query kind.
- About 110 top-level `lib/*.ts` modules (224 files in `src/lib` including `__tests__`). About 41 are per-feature `*At(snapshot)` readers over `snapshot.livelihoods.*` and similar. Tests: 688 `it/test` cases across `lib/__tests__` and `hooks/__tests__`.
- `viewer/scripts/`: 17 files. Ten are Playwright QA/perf runners; `validate-connected-records.mjs` bundles `lib/validateConnectedRecords.ts` with esbuild.
- Verified: `tsc --noEmit -p tsconfig.app.json` exits 0 with no output. `eslint src -f unix` did not lint: ESLint 9 has no bundled `unix` formatter (exit 2), so lint is unverified this run.

**Findings**
1. [med perf] Cold open is dominated by worker decode, and the decode is not split further. Evidence: `docs/superpowers/progress/connected-world-rework-viewer-compatibility/archive-profile.json` (12 worker samples): decode median 1,078 ms (974–1,221), main-thread receive 365 ms, read 37 ms, longest single receive 108 ms; overall load median 1,733 ms. Why it matters: JSON.parse, two validation passes, v6 expansion and the hash are all inside "decode" and unmeasured. Action: add sub-marks in `answerDecodeRequest` (`bundleDecode.ts`, the `chronicler:bundle-decoded` mark) before optimizing.
2. [med perf/duplication] History and timeline are validated twice on every file load. `bundleValidation.ts:146-160` (in `validateBundleStructure`, legacy path via `bundleFile.ts:parseBundle`) and `:213-224` / `:181-186` (in `validateViewableBundle`, `bundleFile.ts:99-100`) both walk every snapshot and the event rows. Action: one pass with the same messages. Cost unmeasured.
3. [med duplication] Validator helpers are copied into lib modules: `const object` 43×, `finite` 35×, `count` 30×, `amount` 23×, `integer` 13× (about 144 lines). `count` has at least six variants: `Number.isInteger` vs `Number.isSafeInteger`, with and without `finite`/`typeof` (e.g. `workshops.ts` vs `timberOrders.ts`). Action: a shared `lib/recordGuards.ts`, preserving each variant or documenting the intentional correction (AGENTS.md: describe corrections separately).
4. [med duplication] The `*At` readers repeat the same envelope: `snapshot as unknown as Record<string, unknown> | null` 46×, `livelihoods.schema_version !== 1` 77×, `source_turn + 1 !== snapshot?.turn` 22×. Example: `workshops.ts:44-52` and `timberStock.ts:53-60`. Action: a generic `readLivelihoodRecord(snapshot, key, check)`. Roughly 150 lines.
5. [med dead-code] Two exports have no consumers: `factionColorDark` (`colors.ts:20`) and `movementsOf` (`movements.ts:68`). Ten more are used only by tests: `famineSpans` (`food.ts:90`, 4 test files), `recipePreparedMismatch` (`whatIf.ts`, 16 lines), `templeEventText` (`faiths.ts`, 8 lines), `apprenticeshipAt`, `hasGovernanceRecord`, `reformKind`, `clearComparisonGallery`, `investigationBookmarkReference`, and the test hooks `setDecodeWorkerFactory` and `setReferenceObjectPatches`. A further 46 exports are used only inside their own module and could drop `export`. Lib module-level dead code: none found (every module has a non-test importer, or is referenced by URL or by a script).
6. [low dead-code] `hooks/useBundle.ts:7` re-exports `parseBundle`. Its only consumer is `lib/__tests__/transport.test.ts:6`. Action: import from `lib/bundleFile` in the test and remove the re-export.
7. [med type-safety] 174 `as unknown as` casts in `lib`. One non-test `any`: `hooks/useLiveConnection.ts:260-263`, where live WebSocket messages are `JSON.parse`d into `msg: any` and dispatched on `msg.type` with no runtime shape check. Action: validate `init`/`turn` payloads with the same guards as bundles.
8. [med fragile] The lint invocation is broken. `npx eslint src -f unix` exits 2 on ESLint 9. The `eslint.config.js` globs cover only `ts/tsx`, so `scripts/*.mjs` are unlinted. Action: use `npm run lint`, or install `eslint-formatter-unix`.
9. [med dependency] Undeclared dependencies. `playwright` is required by ten `viewer/scripts/*.mjs` (e.g. `perf-viewer.mjs:504`) and by the Python QA scripts (`qa_event_ledger.py:10`), and it is in neither `package.json` nor `package-lock.json`. `esbuild` is used at `scripts/validate-connected-records.mjs:19` and resolves only transitively through vite.
10. [low perf] Per-call locale work remains: `lib/whereToLook.ts:9` (`show`), `commonsRules.ts:119` and `recoveryChain.ts:630` each call `toLocaleString` with new options. `entityHistory.ts:44` already shares one `Intl.NumberFormat`, which is the rework fix (4,870 ms → 612 ms index build, `connected-world-rework-viewer/README.md:21-30`). Also `localeCompare` runs inside sort comparators with no shared `Intl.Collator` (e.g. `entityHistory.ts:328`).
11. [low bug-risk] `bundleDecode.ts` `answerDecodeRequest` starts `identifyArtifact` before parsing and does not await it on a parse error, so a rejected hash could surface as an unhandled rejection. The main-thread path (`bundleFile.ts` `decodeBundleBytes`) hashes after parsing, so the two paths differ in timing. Unverified whether `identifyArtifact` can reject.
12. [low perf/memory] `bundleFile.ts` `decodeBundleText` copies the whole file to a string before `JSON.parse`, about 38 MB for the profiled input. Unmeasured.
13. [low test-gap] 28 `lib` modules have no same-named test. `checkpointFile.ts` has zero direct test importers, but `bundleFile.ts:96-99` runs `checkpointNotice` on every upload. `lib/eventLedger.test.ts` and `lib/settlementInspection.test.ts` sit outside `__tests__`.
14. [low docs] Dependency freshness is unverified: no registry query was run. Lockfile pins: react 19.2.4, recharts 3.8.0, vite 7.3.7, typescript 5.9.3, d3-force 3.0.0 (its last release is from 2022 as far as I know), vitest ^4.1.0, jsdom ^28. All declared runtime and dev dependencies are used (checked by import and config grep). `d3-force` is used only in `components/TerritoryMap.tsx:10`.

**Demo vs production (f): separated.** No production module imports `src/demos/**`, `components/phase75/__demo__/**` or `*Fixture.ts` (grep). `vite.config.ts` has no `rollupOptions.input`, so the three root `*-demo.html` pages are dev-only; this is read from config, not a build. The constructed-bundle notice (`ConstructedNotice.tsx`, `lib/constructedExample.ts`) requires explicit `metadata.constructed` and does not infer from the filename.

**Simulation depth**
- The loaders already validate per-turn ledger identities (`timberStock.ts` `timberResidual`). A viewer panel could surface the same closure check across every turn, so the viewer flags an unbalanced ledger rather than rendering it.
- `bundleIndex` covers history and events but not the livelihood records; per-turn timber and workshop readers rebuild their objects on each scrub. A keyed index would make the scrub cost independent of run length.
- Live mode (`useLiveConnection.ts:307-350`) copies `history` and `events_timeline` on every turn (`[...history, snap]`), which resets the WeakMap index each turn. A windowed or append-only index would keep long live runs responsive.

**Confidence**: Verified by grep and direct reads: import map, export consumers, helper counts, validation double pass, demo separation, dependency imports, and the typecheck pass. Verified from the recorded profile JSON: decode and receive medians. Inferred or unverified: the split of decode time, the cost of the double validation, lint status, registry freshness, and whether `identifyArtifact` can reject. Only the two permitted commands were run.
