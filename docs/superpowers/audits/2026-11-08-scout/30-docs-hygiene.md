**Findings**
1. [high, docs] Current-status claims disagree. `README.md:20-24` names PR #69 (2026-11-04) as the start point. `docs/RECOVERY.md:1-10` says "Updated 2026-11-06 after PRs ... #92" and stops there. `AGENTS.md` names PR #81 as the latest merge. `docs/CONTINUATION.md:1-5` names PR #99 and is the only file that is current. The top-level docs record neither PR #100 nor the main SHA `c3d752fa` (`grep '#100'` over README, AGENTS and `docs/*.md` finds no hit). Action: make CONTINUATION the single status record; have README and AGENTS link to it and drop their PR numbers; add a "main at SHA" line that is updated on each merge.
2. [med, docs] Test lane instructions conflict. `README.md:173` gives `python -m pytest -q` as the "no-Rust Python lane". `AGENTS.md` names `scripts/run_python_oracle_checks.py` (chunked, 110 s per chunk, guarded) as the bounded lane. `docs/DEVELOPMENT.md:100` endorses plain pytest "in a clean environment". Action: README should defer to DEVELOPMENT.md's guarded commands.
3. [med, docs] `docs/RECOVERY.md` is a dated index. It keeps superseded "current source" entries (PRs #73–#92) above the newer status in CONTINUATION. A reader can take the first status it sees as current. Action: keep RECOVERY to the source-identity table and move the per-PR narrative into the progress ledger.
4. [low, docs] Runtime versions agree across files: Python 3.13+ (`pyproject.toml:5`, README:15, DEVELOPMENT:43), Rust 1.85 (`chronicler-agents/Cargo.toml:5`, README:17), CI Node 20.19.0 (`.github/workflows/tests.yml:545`). `docs/DEVELOPMENT.md:340` says the cloud container has Node 22. Not a contradiction, but README never states the Node requirement.
5. [med, docs] Superseded audits sit in the live tree. `docs/superpowers/audits/` holds 13 entries. Three are dated full audits (2026-03-29: 210 lines; 2026-04-02: 256 lines; masteraudit/opusaudit4-1-26 are marked "Historical snapshot"). Grep for the names finds only the file itself for the two 03-29/04-02 audits; `masteraudit`, `opusaudit4-1-26` and `4-4-26opusaudit` each appear in three files (the audits cross-link). `4-4-26opusaudit.md` is a verification rewrite, not a draft, which the filename does not say.
6. [med, hygiene] Tracked logs and profiles with no ignore rule. 69 `.log` files (320 KB; 24.6 KB for `offline-v4.log` alone, mostly under `docs/superpowers/progress/connected-world-*`), one `.cpuprofile` (`docs/superpowers/progress/connected-world-rework-viewer-compatibility/residual-index.cpuprofile`, 56 KB) and 18 PNG screenshots. `.gitignore` (28 lines) has no `*.log`, `*.cpuprofile`, `.coverage`, `htmlcov/`, `.mypy_cache/`, `.ruff_cache/`, `.hypothesis/`, `*.so`/`*.pyd`. No tracked file matches `.pyc`, `.so`, `.db` or `.whl`; the only tracked matches for the missing patterns are the logs, the profile and the PNGs. Action: add those patterns and untrack new generated logs.
7. [med, hygiene] Archiving by move collides with pins and byte rules. `docs/DEVELOPMENT.md:335` says evidence JSON "must stay byte-for-byte unchanged when moving". Tests and scripts name exact paths (finding list above), `scripts/refactor_preflight.py` treats `docs/workflows` as pinned, and `docs/superpowers/progress/*.json` records hashes and paths. Archive by `git mv` therefore breaks tests and the hash-recorded provenance. Recommended: archive in place (add an `ARCHIVE.md` index, exclude historical trees from search), or move only files with no hits in `tests/`, `scripts/` and `docs/`, after running `scripts/refactor_preflight.py` on them. Never edit the JSON bytes.
8. [med, hygiene] Largest tracked files: about 18 of the top 30 are under `docs/` (largest `connected-world-rework-viewer-compatibility/complete120-readers.json` 508 KB; `rework-cwr1-held/metrics.jsonl` 984 KB). Eight are `viewer/src/__fixtures__/*.json` bundles (largest `systems_bundle.json` 672 KB), plus `uv.lock` 204 KB, `viewer/package-lock.json` 192 KB, `chronicler-agents/src/ffi/mod.rs` 300 KB and `scripts/connected_world_screens.py` 196 KB. The fixtures are imported by viewer tests (not checked in detail).
9. [med, docs] Sprawl concentrated in evidence. `docs/superpowers/` holds 39 `.jsonl` files (about 5.8 MB), most of them per-screen `metrics.jsonl` run outputs under `progress/`; `docs/superpowers/analytics/` 376 KB. These repeat each other per screen run. Action: keep one summary per screen family in git; move raw run output to a release asset or an external store.
10. [low, docs] `docs/CONTINUATION.md` is 2,298 lines of mostly superseded "next task" entries. The file itself says its top section supersedes older ones. Action: move history below the first section to `docs/superpowers/progress/continuation-history.md`; nothing in code reads CONTINUATION (grep above).
11. [med, docs] Older audit cross-check. Of the 12 chosen findings (below), 11 are fixed in current code and 1 (C3) is partly present. The audits are not a reliable worklist, and their severity labels are not updated anywhere.
12. [low, hygiene] `docs/README.md` maps docs to code-comment links but says nothing about archive status; new readers cannot tell live notes from closed notes (for example `docs/integration/*-candidate.md`, `needs-*`).
