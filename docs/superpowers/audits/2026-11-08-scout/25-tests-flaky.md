## 25 Python test suite health and flakiness
**Map**
- `tests/`: 540 `.py` files, 221k lines (460 `test_*.py`, 182.8k lines). `conftest.py` (183 lines) gives `make_civ`, `make_world`, `sample_world` and bridge-world fixtures. `live_session_harness.py` (206) drives live-server tests; `reference_baselines.py` (21) reads frozen copies under `tests/fixtures/reference_baselines/26e18…/`.
- `pyproject.toml:24-30`: testpaths=tests, pythonpath=src, two markers (`slow`, `native`); no addopts, no timeout plugin.
- `scripts/run_python_oracle_checks.py` (582 lines): 76 chunks, 337 node IDs, 252 unique files, each its own pytest process under `python_oracle_guard.py` (108 lines), 110 s `subprocess` timeout, stops at first failing chunk. `DESELECT` (line ~ 'not test_real_cli_and_cross_process…') removes the cross-process hash-seed tests.
- `scripts/refactor_preflight.py` (483 lines) is the read-only pin finder; `scripts/testing/native_shards_manifest.json` is a dormant 2-shard whole-module partition (263 + 197 entries).

**Findings**
1. [med] flaky — Wall-clock polling and tight assertions in process tests. `tests/test_what_if_process.py:38-40` (4 s deadline, 0.02 s poll), `:62` (spawns a `sleep(60)` grandchild), `:86` (`assert time.monotonic() - start < 5`). A loaded 4-core host with 32 scouts or CI can break `:86`. Action: replace with an event/`join` on the job thread and drop the absolute bound.
2. [med] flaky — `tests/test_python_qualification.py` has about 12 busy-wait loops with 5–15 s deadlines and 0.01–0.05 s sleeps (`:298-299, :331-344, :439-440, :538-562`). Whether these run in the oracle lane is unverified. Action: use `threading.Event` waits with explicit timeouts.
3. [med] flaky — Live-server tests use 10 s polling deadlines (`tests/test_live_integration.py:873-874, :953-954`; `live_session_harness.py:60,107,135`). They bind `port=0` (good, no fixed port), but depend on wall time. The `localhost:1234` strings are mock endpoints only.
4. [med] test-gap — 13 silent data-dependent skips in `tests/test_rivers.py:109,124,143,165,190,207,226,350,378,412,435` ("No adjacencies"). These trigger on `generate_world(seed=42)` returning a world with no adjacency, so the test cannot run and reports "skipped", not failed. Action: pin a seed/world that has adjacencies and assert.
5. [low] flaky — Global RNG mutation: `tests/test_validate.py:281` calls `random.seed(42)` on the global RNG and then uses it at `:282`, so later tests in the same process inherit state. `tests/test_practice_growth_observer.py:72` calls unseeded `random.random()`. Action: use `random.Random(42)` locally.
6. [low] fragile — Thread and pool use in ~8 files (`ThreadPoolExecutor` in `test_governance_capture.py`, `test_governance_sequence.py`, `test_session_comparison.py`, `test_memome_candidate_preview.py`, `test_campaign_order_preview.py`, and others), plus `threading.Thread` in `test_state_checkpoints.py:261` and `test_live_integration.py:143`. Whether every `Event.wait`/`join` has a timeout is unverified.
7. [low] fragile — `tests/test_world_gen.py` contains a cross-process hash-seed test that the oracle lane deselects (`run_python_oracle_checks.py`, DESELECT). It runs only in full-suite runs, so the oracle lane does not cover it.
8. [med] test-gap (oracle coverage) — The oracle lane lists 246 of 460 `test_*.py` files (214 not listed, roughly 47%). Most unlisted files are native-only or detached, but this is an unmeasured gap.
9. [med] duplication — 72 files match `*native*`; 55 have a same-stem non-native sibling (for example `test_X.py` and `test_X_native.py`). Pairs test different runtimes, so they are not duplicates to delete, but they double the fixture code. Count of duplicated fixture-builder lines: unverified.
10. [med] dead-code (test-only) — 13 harness modules (table in (d)) are reached from production only through `scripts/*` or other detached modules. About 13.7k lines of tests (27 files, 7.5% of `test_*.py` lines) exercise them.
11. [low] docs — Oracle chunk timing is stale. `docs/performance/bundle-v6.md:204` records "PASS in 76.6 s, largest chunk 29.5 s of 110 s" when the lane had fewer chunks; `workflow-scaling-2026-10.md:132` records 18 chunks. The runner now has 76. Current per-chunk headroom is unknown without a run.
12. [low] fragile — Collection is clean: `pytest --collect-only` gave "11972 tests collected in 34.25s" with no collection errors in the tail. No xfail markers (0). Warnings summary not visible in tail.

**(a) Skip inventory** — 272 skip-type call sites across 150 files: 147 `pytest.importorskip` (121 `"chronicler_agents"`, 17 `"pyarrow"`, 2 `"arro3.core"`, 7 other native submodule), 96 `pytest.skip(...)` calls in bodies, 29 `pytest.mark.skipif`. Zero `xfail`. Roughly 195 of the 272 lines mention native, Rust, extension, build or compiled (approximate, regex on line text). Reasons by kind: native/Rust absent or stale (`chronicler_agents not built`, `Rust crate not built`, `stale chronicler_agents extension binary`, ~60); pyarrow missing (~21); POSIX/Linux platform gates (~12, e.g. `test_python_qualification.py:286,373,414`); environment (hardlinks, filesystem change-time, ~4); data-dependent silent skips (13 in `test_rivers.py`, 2 in `test_feature_matrix.py:276,356`, `test_session_comparison.py:466`, `test_parent_extra_archive.py:296`). Separately, 147 `pytestmark = pytest.mark.native` and 13 `slow` marks. Historical oracle lane reported 28 skips (`bundle-v6.md:204`). Native-only skips are not genuinely broken tests, but they run silently in the offline lane.

**(e) Source-witness and pins** — 54 `tests/fixtures/*inverse*.json` chained layers. Each records a parent commit, a SHA-256 of the file, `current_sha256`, and `patches` (exact old/new text). They name 60 distinct files, 58 in `src/`, `scripts/` or `chronicler-agents/`. `refactor_preflight.py src/chronicler/simulation.py` reports 11 enforced witnesses, and `main.py` reports none. The mechanism: "any edit still breaks the chain", and changes are allowed only through a reviewed inverse layer. Add enforced oracle-chunk and native-shard ownership on top. I did not recount the docs' 83 enforced and 25 digest totals (unverified; would need preflight over every tracked file). Refactoring `simulation.py` therefore needs a new inverse layer, not a test edit.

**Simulation depth**
- Replace the silent `test_rivers` skips with a seeded world that is guaranteed to have adjacencies, so the river mask is actually tested.
- Add per-chunk timing history (the receipt already has `chunks[].seconds`; commit a trend) so chunks can be rebalanced before they reach 110 s.
- Move process-lifecycle tests (`test_what_if_process.py`, `test_python_qualification.py`) onto event-based waits so they are deterministic under load.

**Confidence** — Verified by collect-only run, grep and scratch Python over the skip markers, oracle chunk definitions, witness fixtures and preflight output on `simulation.py` and `main.py`. Inferred: flake risk from wall-clock patterns (not reproduced; no targeted test was run). Not run: the oracle lane and the two focused files (budget). Oracle per-chunk timing not measured now.
