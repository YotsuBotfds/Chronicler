## 14 Technology, techniques, scholarship, science and learning
**Map**
- Five parallel knowledge models: legacy era tree `tech.py` (163 lines, `TechEra` on `civ.tech_era`); practice-based `techniques.py` + `techniques_state.py` (1238 + 190, 8 domains, ~40 techniques, derived eras); seats of learning `scholarship.py` + state (1082 + 111); academy-funded science `scientific_claims.py` (648) and explicit agendas `scientific_research.py` (677), each with `_state` and audit modules (`scientific_receipts_audit.py` 395, `scientific_research_audit.py` 507); learning services and cohorts (`learning_services.py` 668, `learning_cohorts.py` 478, `reform_services.py` 559). Tech specialisation `tech_focus.py` (441) hangs off the era advance.
- Turn loop (`simulation.py`): Phase 4 is `tick_techniques` if `_techniques_on` (simulation.py:2205-2208), else `phase_technology` (simulation.py:1579, calls `tech.check_tech_advancement`, line 1585). `techniques.DEFAULT_ENABLED_FOR_NEW_WORLDS = True` (techniques.py:73), so the legacy tree runs only for saved/`--no-techniques` worlds. Scholarship tick at simulation.py:2505-2521; learning services at simulation.py:1922, 2296-2332, 2516-2520. Scholarship, claims, research default off (scholarship.py:69, scientific_claims.py:21; no default constant in the research/learning/reform state modules).
- Nested gating: `tick_scientific_claims` runs only inside `tick_scholarship` (scholarship.py:350-352) and requires scholarship, techniques and claims all on (scientific_claims.py:43-45).
- Rust: `knowledge.rs` (1474) is M59a information packets (threat, trade, religious, movement news), not tech knowledge; driven from tick.rs:653. `learning_work.rs` (579) and `teaching_work.rs` (124) are driven from tick.rs:1583-1717 and pool.rs:190-205.
- Scale: about 8,900 Python lines in the listed modules plus about 2,200 Rust lines.

**Findings**
1. [high] duplication — Two era-advance implementations. `techniques._advance` (techniques.py:789-832) is a copy of `phase_technology` (simulation.py:1585-1625), "kept event for event", but it does not charge the treasury cost that `check_tech_advancement` charges (tech.py:109-113). Eras are therefore free under techniques, and the difference is not labelled as a correction. Same for `techniques._regress` (techniques.py:835) vs `emergence.check_tech_regression` (emergence.py:718). Action: one shared helper in `tech.py`, with the cost difference stated explicitly.
2. [med] bug — `capability_scholarship` is emitted on every call for a scholarship-focus civ, before the affordability check (tech.py:100-106). `check_tech_advancement` runs every turn for every civ (simulation.py:1585), so legacy worlds get event spam. The techniques path emits only on a real invention (techniques.py:568-573). Action: move the emit after the affordability check, documented as a correction.
3. [med] sim-depth/contract — Focus stat modifiers are applied with direct `setattr` (tech_focus.py:387-407), bypassing the accumulator, when called from `phase_technology` (simulation.py:1592-1594) and `_advance` (techniques.py:~812). Era bonuses in the same phase do go through `acc`. Impact in hybrid mode is unverified. Action: route through `acc` or document the exception.
4. [med] fragile — `_focus_applied_deltas` is an undeclared attribute on the pydantic `Civilization` (models.py:565; tech_focus.py:387-420), so it is not in the serialized state. After a load, `remove_focus_effects` falls back to raw modifiers (tech_focus.py:414-416), which differ from the applied delta when clamped. Only `checkpoint_replay.py:85-100` reads it. Whether a resumed run restores it is unverified. Action: declare it as a field; this changes bundle schema, so it needs a compat path.
5. [med] duplication — Scholarship focus discounts are applied in three places: tech cost (tech.py:100-101, literal `0.8`), invention cost (techniques.py:547, `SCHOLARSHIP_COST`), and research (techniques.py:492). Plus `scholarship.research_factor` inside `_research_multiplier` (techniques.py:496-498). Action: import the constant; document the stacking.
6. [med] duplication — The contact channel tuple is restated in `techniques_state.py:43`, `contact_ledger.py:55`, and `languages.py:133`. `techniques_state` says tests pin equality. Action: a single source.
7. [med] sim-depth — Diffusion between polities exists only in techniques mode, and only through contact-ledger edges when the ledger is on: `NEIGHBOUR_FLOW` applies only to same-controller borders (techniques.py:266-283). Legacy `tech.py` has no diffusion; `K_TECH_DIFFUSION_RATE` (tuning.py:278, read at tech.py:98-99) only divides the era cost, so the name misleads.
8. [med] sim-depth — Tech effects reach war (battles.py:147, action_engine.py:787), economy (economy.py:780), ecology (ecology.py:604), finance (finance.py:760, 909), and health (epidemiology.py:555, 657; epidemic_care.py:289) only under techniques. Legacy-tree effects are just `ERA_BONUSES` (tech.py:41-49) plus focus stat modifiers that touch economy, military, culture and stability, not health (tech_focus.py:308-385).
9. [med] sim-depth — "Lost knowledge" has no explicit model. It occurs only through seat falls (scholarship.py:666 `_fall`, `FALL_LOSS` line 112), generic forgetting (techniques.py:90), and era regression. Archive copies are capped at `SEAT_COPIES_CAP = 3` (scholarship.py:121).
10. [med] complexity — Pause/lab adapters: `pause_policy.py` (38), `pause_transport.py` (43), `pause_academy.py` (87) are thin wrappers over `lab_*`, with CONTROL/TARGET/STAT triples repeated in `what_if.py:30-34`. `pause_transport.apply` (pause_transport.py:23-33) duplicates the timeline event-ID logic. Private cross-imports: `lab_academy.py:39` (`_require_physical_hybrid`) and `pause_academy.py:45` (`_boundary`).
11. [med] complexity — The science audit modules (about 900 lines) are consumed only by `expansion_audit.py:20` and `expansion_compare.py:17-18` (tooling), not by the runtime. `memome_candidate_preview.py` (173) is used only by `scripts/memome_candidate_preview.py` and tests, and `tests/test_memome_candidate_preview.py` is named in `scripts/testing/native_shards_manifest.json`, so it is pinned.
12. [low] dead-code — None verified. Every listed module has a caller (see Map and the table). `learning_services.native_learning_counts` (learning_services.py:152) is called at line 258. `culture_projection_range` is read (culture.py:343, action_engine.py:1143).

**Simulation depth**
- Give the legacy and techniques era paths one cost model and make the treasury effect of era advance explicit; the current split makes eras free in the default world (techniques.py:73).
- Diffuse tech along the contact ledger across polities by channel-specific trade routes, not only through same-controller borders (techniques.py:266-283).
- Add an explicit health path for technique-driven knowledge (medicine domain, CFR floor) with a tech-specific event, and let scholarship seat falls feed a loss ledger (scholarship.py:666-707) so lost knowledge is measurable.
- Give the legacy tree (`tech.py`) its own diffusion or retire it in favour of techniques for new worlds.
- Connect learning institutions to economy and demography (scholar agents already drawn by `seat_pull`, scholarship.py:985) beyond invention research.

**Confidence**
Verified by grep and reads: all call sites and gating listed above, the era-cost split, the duplicated event, the `_focus_applied_deltas` attribute, and the channel tuples. Inferred or unverified: whether a resumed run restores focus deltas, whether direct focus mutation in hybrid mode changes outcomes, whether the Rust learning paths are exercised by default, and the exact behaviour of the Rust info-packet phase. No tests were run; read-only, no state-changing commands.
