## 24 Viewer components, demos and UX
**Map** —
- `viewer/src/main.tsx` → `App.tsx` (221 lines) → `components/phase75/AppShell.tsx` (1,842 lines, the only shell). Pulls the phase75 panels, `systems/` (71 panels, 8,301 lines), and lazy chunks via `phase75/lazyPanels.ts`.
- Demos: `combined-inspection-demo.html`, `event-ledger-demo.html`, `settlement-inspector-demo.html` at `viewer/` root. `vite.config.ts` sets no multi-page input, so these exist only under `npm run dev`; the `scripts/qa_*.py` files assume port 5173.
- 124 component/demo files; 9 are reached by no entry point (see 1). Four demo-only components and two lib modules sit in the production tree (see 12).
- Map is one fixed SVG (`phase75/MapViewport.tsx:210`, `viewBox 0 0 1000 640`); no canvas.
- Systems tab: `systems/SystemsPanel.tsx` dispatches 16 panels (`PANELS`, lines 24–41) via one tab strip.
- Styling: Tailwind in legacy files (225 utility-class tokens) beside 1,625 custom `phase75-*`/`systems-*` classes; CSS is dark-only (`app-shell.css:2`).

**Findings**
1. [high] dead-code — Nine legacy components are unreachable from `main.tsx` or any demo: `ChroniclePanel`, `EventLog`, `FactionDashboard`, `Header`, `RegionMap`, `SetupLobby`, `StatGraphs`, `TerritoryMap`, `TimelineScrubber` (2,096 lines). Their only importers are tests (`components/__tests__/components.test.tsx`, `SetupLobby.test.tsx`, `RegionMap.test.tsx`, and the "legacy setup lobby" block of `FeatureRequests.test.tsx:67`). Evidence: static import trace from `src/main.tsx` and the three demo entries; name grep over `viewer/src`, `tests/`, `scripts/`, `viewer/scripts`, `chronicler-agents/` finds no non-test use; `docs/superpowers/` mentions are historical. Action: delete with their tests (~440 test lines). Pinned: no hits in `tests/` or `scripts/testing/`.
2. [med] complexity — `AppShell.tsx` holds 32 `useState` calls (lines 583–631, 1504), 10 `useMemo`, and about 365 lines of pure helpers (lines 127–492) such as `buildChronicleFeed`, `computeAtlasLayout`, `buildRegionConnections`, `sortCivilizations`. `buildEventFeed` already lives in `appShellHelpers.ts`, so placement is inconsistent. Action: move helpers to `lib/` for direct unit tests; group setup-form state into one reducer.
3. [med] perf — Per-render work is not memoized in the shell, so every scrub tick repeats it: `buildChronicleFeed` (`AppShell.tsx:665`), `buildCivilizationViews` (656), `computeAtlasLayout` (712), `buildEventFeed` (749). `exactSnapshot` is an O(history) `filter` (`lib/historyComparison.ts:25–27`) called twice per render (`AppShell.tsx:696`, `726`). Action: key memos on bundle plus turn, and replace `exactSnapshot` with a turn-to-row map that `rowIndex` (`lib/civRows.ts:39`) already builds.
4. [med] duplication — Systems panels repeat primitives rather than bodies. Line-level similarity between panel pairs is low (difflib 0.17–0.34), so this is shell and vocabulary duplication, not copy-paste: 133 `<section className="systems-section"><h3>` sites, 179 `systems-table-wrap` tables, 39 files each defining `const show = …` number formatter, 17 defining `words` (underscore replace), and about 10 files with their own page-size constant (`AcademyServices.tsx:6`, `ForecastDecisions.tsx:5`, `EntityHistory.tsx:10`, `RecoveryChain.tsx:39`, `SystemParts.tsx:9,171`, `Transactions.tsx:7`, `RitualGatherings.tsx:8`, `ScientificClaims.tsx:12`, `RegionSystemsDetail.tsx:8`). Proposed generic panel: `SystemPanelFrame({label, note, tiles, children})`, `SystemSection({title, note, emptyText})`, `usePaged(rows, size)`, and one `formatters.ts` (`show`, `percent`, `words`, `notObserved`).
5. [med] duplication — Three copies of Blob download code: `InvestigationPacket.tsx:10–17`, `CompletedRunCompare.tsx:115–122`, `WhatIfPanel.tsx:86`. Extract `lib/download.ts`.
6. [med] a11y — Timeline strip track is `role="img"` with mouse-only `onClick` (`systems/SystemParts.tsx:133–135`). Segment text is dropped below 8% width (line 59), leaving narrow segments reachable only by hover `title` (line 57). Keyboard seeking exists only on the prod `TimelineRail` slider (`phase75/TimelineRail.tsx:97–108`).
7. [med] a11y — `SystemEventList` puts `role="listitem"` on `<button>` (`SystemParts.tsx:190–195`), which overrides button semantics. Systems tablist has no arrow-key roving and the tabpanel has no `aria-labelledby` (`SystemsPanel.tsx:74–89`). `aria-selected` sits on `<tr>` (`CitiesPanel.tsx:93,146`; `LearningPanel.tsx:94`; `MovementsPanel.tsx:102`), which is invalid outside grid roles.
8. [med] a11y — Map overlay toggles encode on-state only by `.active` class, with no `aria-pressed` (`MapViewport.tsx:139–150`); the layer group at lines 156–163 uses `role="radio"` correctly, so the pattern is inconsistent. `SetupRail.tsx:197–199` is a click-only dropzone div with no role, tabIndex or key handler. Map nodes are colour-only (`MapViewport.tsx:85–86`, `lib/colors.ts:15–17`); the civ name is only in `<title>`.
9. [med] scaling — Atlas has no pan or zoom (grep for `zoom|pan|onWheel|transform` in `components/` and `lib/` is empty). Every region gets a circle and a text label, and labels are on by default (`AppShell.tsx:585`), so labels will overlap at hundreds of regions. Faction hue is `hash % 360` at fixed S/L (`lib/colors.ts:15–17`). Pigeonhole gives C(48,2)/360 ≈ 3.1 expected identical-hue pairs at 48 civs. A scratch simulation with random names (not real civ names) gave 8.0–8.2% of pairs within 15° at 8, 24 and 48 civs, against a random baseline of 8.3%.
10. [med] scaling — Lists and scans are unbounded or unmemoized. `CitiesPanel.tsx:93` maps every `living` row with no limit. `AcademyServices.tsx:19` filters the full history on every render. `DebtHolders.tsx:93–94` runs per-scrub filters over history and events. Event lookups are fine: `typedEventsUpTo` is indexed (`lib/bundleIndex.ts:147`).
11. [med] state — Module-level singletons carry UI state: `lib/entityHistoryNavigation.ts` (a `pending` variable plus `window` event `chronicler:entity-history`, consumed in `SystemsPanel.tsx:52–58` and `EntityHistory.tsx:20–21`), and `lib/comparisonGallery.ts:15–16`. `SystemsPanel.tsx:52–60` and `entityHistoryNavigation.ts` are minified in style. `AppShell.tsx:802–830` syncs derived state through `useEffect` (`syncSetupDefaults`, `syncOverlayPreset`), which should be derived or keyed.
12. [low] complexity — Demo-only code lives in the production tree: `phase75/GroupedEventLedger.tsx` (140), `phase75/SettlementInspector.tsx` (123), `phase75/__demo__/`, `lib/eventLedger.ts` (85) and `lib/settlementInspection.ts` (197). Reached only from the demo entries; `docs/viewer/*.md` and `scripts/qa_*.py` reference them. Action: move to `src/demos/`, do not delete.
13. [low] test-gap — No direct test for `MapViewport.tsx`, `RightInspector.tsx` (489 lines), `TimelineRail.tsx`, `SetupRail.tsx`, `MapLayerMarks.tsx`, `PanelLoading.tsx`, `ComparisonGallery.tsx`, `InterestingPeriods.tsx`, `InvestigationPacket.tsx`, `RegionInvestigation.tsx`, `HouseholdMobilityEvidence.tsx`, `ResearchAgendas.tsx`, `HarvestCover.tsx`, `ForecastConstruction.tsx`. Several run through `phase75/__tests__/AppShell.*.test.tsx`. `ForecastDecisions` is covered by `HarvestForecasts` tests. No axe or a11y assertion exists in vitest; the only a11y check is opt-in `scripts/qa_combined_accessibility.py`.
14. [low] fragile — Twelve component files are pinned by hash in `tests/fixtures/*_source_inverse.json` and `tests/test_scenarios_candidate_witness.py:45`, including `systems/Granaries.tsx`, `GranaryStorage.tsx`, `Transactions.tsx`, `ForecastConstruction.tsx`, `ForecastDecisions.tsx`, `LearningPanel.tsx`, `AcademyServices.tsx`, `HarvestForecasts.tsx`, plus `WhatIfPanel.tsx`, `CompletedRunCompare.tsx`, `MigrationEvidence.tsx`, `HouseholdMobilityEvidence.tsx`. Any refactor of these needs `scripts/refactor_preflight.py` first, and no hash may be rewritten to pass.
15. [low] UX — No window-level keyboard shortcuts (zero `window` keydown listeners in `components/`, `hooks/`). Play/pause is button-only (`TimelineRail.tsx:78`).

**Simulation depth** (viewer UX for a grand run; each grounded in code above)
- Overview: `InterestingPeriods.tsx` exists, but nothing draws a run-wide turning-point strip across systems, wars and epidemics on one track.
- Timeline: `TimelineRail` maps the whole run to one track (`turnToPercent`), with no zoom or brush (grep empty). Thousands of turns mean several turns per pixel. Add a zoomable window with era and event marks.
- Entity pages: `EntityHistory` and `CivilizationHistory` exist, but the civ view does not join its systems tabs. Cross-links use the global event in (11).
- Comparison: `AppShell.tsx:599` `compareMode` is only `"runs" | "batch"`. No same-run turn-versus-turn diff. Add a diff of two snapshots reusing `exactSnapshot`.
- Export: three download sites (see 5), no CSV of the per-turn series that `StatGraphs` plotted (legacy, see 1).
