## 04 Economy, money, credit and accounting ledgers (economy-money)

**Map**
- `economy.py` (2137 lines): per-turn goods sub-sequence called from Phase 2 (`compute_economy`, economy.py:1742): production (`compute_allocated_production`), demand (`compute_demand`, :995), tatonnement prices (:1904-1969), trade allocation (`allocate_trade_flow`, :1105), stockpile accumulate/decay/consume/cap (:429-513), then signals (farmer modifier, merchant margin, treasury tax and tithe, :2057-2135).
- `money.py` (753 lines): the payment seam. `pay`/`quote` (:408, :572) move whole bills between accounts (civ treasury, firm cash, agent wealth, sinks, relief funds, escrow). Its book `MoneyBook` is persisted per package; `flows_for_turn` and `totals_for_turn` feed the ledger.
- `wealth_accounting.py` (1284) plus `_state.py`: observation-only A1 ledger (`--wealth-accounting`, default off). It reads balances and writes closures; it is not meant to write balances.
- `domestic_credit.py` (989) plus `_state.py`: lenders are merchants, guilds and cities; principal and repayments move through the native pool. `_Ledger` (:705) is a debug reconciliation gated by `CHRONICLER_CHECK_RESOURCES`.
- `production_ledger.py` (497): read-only per-slot ledger, built only with the sidecar or `CHRONICLER_CHECK_RESOURCES=1`.
- `finance.py` (1547), `transaction_receipts*.py`, `public_purchase_receipts.py`, `resources.py`, `demand_signals.py`, `transport.py`: only skimmed (see Confidence).
- Turn-loop callers: `simulation.py:330-420` (trade bonuses), `:603` (base income), `:654` (mines), `:1805-1823` (treasury tax carry).

**Findings**
1. [high] bug — Treasury money is created outside the seam in many places. Examples: base income `civ.economy // 5 + len(regions)*2` (simulation.py:603), +2/+3 trade and self-trade bonuses (simulation.py:339-353), +2 per mine (simulation.py:654), and 5% of merchant wealth as treasury tax (economy.py:2117; simulation.py:1813-1818). `wealth_accounting.py:71` labels the tax "debited from nobody". rg finds about 55 direct `civ.treasury +=/-=` sites across `src/chronicler` (for example politics.py:604-605, action_engine.py:958-959, factions.py:430). Why it matters: there is no conservation identity for the treasury stock, and the seam does not cover most treasury flows. Action: decide which of these are intended fiat sources, route the rest through one `credit_treasury`/`debit_treasury` helper that writes a flow record, and label fiat sources in one table.
2. [high] fragile — Conservation checks are logged, not enforced. `economy.conservation` (economy.py:1837-2037) is read only by analytics (analytics.py:2207) and production_ledger (production_ledger.py:334). The production check raises only under `CHRONICLER_CHECK_RESOURCES=1` (production_ledger.py:80, 279-283). In wealth_accounting, observe mode stores `closures` booleans (wealth_accounting.py:341-342, 388); strict mode raises only on native `balance_closure` (wealth_accounting.py:1160-1163), not on the legacy identity. Action: make a default-on assertion for money-seam closure (the `check_book` checks already exist, money.py:734) and record the rest as diagnostics.
3. [med] bug — Non-atomic pairwise failure. In `pay`, `_native_pairs` moves wealth first (money.py:585), then the code can raise `MoneyError` for a row that was not paid in full (money.py:592-595). The native transfer is already applied when the error fires. The seam's floor-based pre-read `_wealth` (money.py:404) uses `floor(w*1000)` on f32 values; whether the native check agrees at the boundary is unverified. Action: check the native result before the Python raises or make the pre-read match the native rounding; add a boundary test.
4. [med] fragile — Silent clamps create or destroy goods. `accumulate_stockpile` sets negative stock to 0 and reports it as an "artificial source" (economy.py:441-454, 449-451). `apply_stockpile_cap` destroys overflow (economy.py:495-513). Storage and transit decay destroy goods, but they are counted (economy.py:398-422, 1991-1992). Because exports are drawn from `available_goods`, the clamp should be unreachable except through float error. Action: assert the clamp is zero (or track it with a tolerance) and keep `clamp_floor_loss` as a hard diagnostic.
5. [med] fragile — Division and rounding guards hide errors. `compute_prices` floors supply at 0.1 (economy.py:1035), so an empty market reads as 10x demand. `derive_food_sufficiency_from_stockpile` clamps to [0, 2] (economy.py:467). Domestic credit quantizes guild and city purses to 4 decimals (domestic_credit.py:116, :178-179) and floors lendable amounts (:418, :443). Action: keep the guards but count how often each fires, and log quantization loss into the books.
6. [med] duplication — Money-side branching is copied at each treasury credit. `simulation.py:330-355` has three `if acc is not None: acc.add(...) else: x.treasury += n` blocks; the same pattern appears at :603, :654 and in `money._move_treasury` (money.py:499-506). Action: one helper, same behavior.
7. [low] fragile — Private world attribute holds treasury-tax carry: `world._treasury_tax_carry` (simulation.py:1810, :1823; checkpoint_replay.py:173; wealth_accounting.py:278). Whether it survives serialization or checkpoint restore is unverified. Action: confirm it is in the saved state or move it into a declared state object.
8. [low] dead-code — `INFRASTRUCTURE_DISCOUNT = 1.0` "placeholder, no roads yet" (economy.py:72) is multiplied into transport cost (economy.py:539). It is referenced only by src and `tests/test_economy_m43a.py:15`. Action: inline or delete with the test import.
9. [low] duplication — `TITHE_FOOD_GATE = 0.5` is a local constant (economy.py:2124), duplicated in the Rust `economy.rs`. Action: move to a module constant and mirror it in one place.
10. [low] sim-depth/docs — `compute_transport_cost` takes `min(river, coastal)` (economy.py:540), so river and coastal discounts never stack. Intent unverified (no comment).
11. [low] sim-depth — `compute_demand` sets craft demand to 0 (economy.py:1013), and no region harvests crafts (economy.py:91-93). The craft category is therefore inert in pricing and trade. Action: connect it to cities or remove the category from pricing.

**Simulation depth**
- Goods: 9 goods in 4 categories, with one price per category per region (economy.py:51-106, 1024-1037). Prices are a demand/supply ratio, not market clearing. Tatonnement stops after 3 passes (economy.py:1895-1969).
- Trade: routes are adjacency-only, with a fixed one-tick carry of one unit per merchant and no inventory carried across turns (economy.py:1044-1069, 1118, 1105-1176). Adding multi-tick inventory, capacity per route and caravan losses would deepen it.
- Money: no price-to-wage link and no money supply beyond the fiat sources in finding 1. Routing wages (the seam's `TREASURY_AGENT_PURPOSES`, money.py:104) through a price index would make it a real monetary loop.
- Specialization: production uses fixed resource slots with labor curves (economy.py:700-906). Nothing responds to relative prices, so specialization is not an outcome.
