## 02 World model, schema, world generation, scenarios and tuning
**Map**
- `models.py` (1629 lines): ~80 Pydantic/dataclass models. Core state: `WorldState` (83 public + 17 private fields, models.py:1106), `Region` (61 fields, :416), `Civilization` (52, :565), `GreatPerson` (41, :655), `Army` (25, :865), `TurnSnapshot` (57, :1414), `CivSnapshot` (37, :1366).
- `world_gen.py` (664): template regions (12, lines 29-40), civ templates (6, lines 44-49), procedural path above 12 regions (`resolve_worldgen` :486, `_procedural_regions` :500), `generate_world` :515.
- `scenario.py` (760): `ScenarioConfig` (:79) with 22 keys, `load_scenario` :105, `apply_scenario` :296, CLI resolution `resolve_scenario_params` :721.
- `tuning.py` (500): ~208 `K_*` key constants, `KNOWN_OVERRIDES` (:287), `load_tuning` (:426), 6 presets (:470+), `get_override`/`get_multiplier` (:444-460, ~345 call sites in src).
- `columnar.py` (159), `record_identity.py` (77): not examined in depth (outside the questions asked).
- Data: 6 `scenarios/*.yaml`, 4 `tuning/*.yaml`.

**Findings**
1. [med] complexity — `WorldState` is a god object: 27 fields gated by `exclude_if` (24 of them `_is_none`) are optional experimental subsystems (models.py:1140-1260: contact_ledger, epidemics, finance, diplomacy, techniques, maritime, gp_agendas, nomads, cities, agent_movements, guilds, scholarship, grain_reserves, health_care, harvest_forecasts, ritual_gatherings, scientific_claims, transaction_receipts, domestic_credit, livelihoods, ...). Each is a separate import in the model file. Suggested: keep the names for bundle compatibility but move each subsystem's type behind a registry so the core model only lists the core fields.
2. [med] docs/bug — `Region.terrain` comment (models.py:418) lists 6 terrains, but geography emits 10 (`TERRAIN_BASE_CAPACITY`, geography.py:101-104: plains, steppe, coast, forest, jungle, marsh, hills, mountains, desert, tundra). `TERRAIN_ECOLOGY_DEFAULTS` (ecology.py:55-72) has no `hills` key and `_procedural_regions` falls back to plains (world_gen.py:503-507), so procedural hill regions silently get plains ecology.
3. [med] dead-code (tuning) — 8 keys are accepted by `load_tuning` with no warning but nothing reads them: `stability.drain.twilight` (tuning.py:29), `ecology.famine_water_threshold` (:47), `ecology.disease_baseline_{fever,cholera,plague}` (:57-59), `ecology.famine_refugee_pop` (:110), `infrastructure.max_temples_per_region` and `infrastructure.temple_conversion_boost` (:199, :201). Checked: the `K_` names and the literal strings have no references in `src/` or `chronicler-agents/src/` other than their definitions and `KNOWN_OVERRIDES`. A user setting these gets no effect and no warning.
4. [med] fragile — `tuning/m53a_frozen.yaml` has list-valued leaves (`substrate_changes:`), so `load_tuning` raises `ValueError` (tuning.py:405-419); a user who passes it to `--tuning` crashes. `tests/test_tuning.py:218-222` only asserts that each file is a UTF-8 mapping, so it does not catch this. Separately, `m53_baseline.yaml` (132 keys) and `m53_pass1_all.yaml` use uppercase Rust constant names (e.g. `AUTONOMY_DECAY`) that are not in `KNOWN_OVERRIDES`, so every key is only a warning and has no effect. These are evidence snapshots, not tuning inputs, and should be labelled or moved.
5. [med] fragile — No schema version anywhere in the core state. `WorldState` has no `schema_version` field and `save`/`load` (models.py:~1290-1330) have no version gate. Compatibility depends on per-field defaults, `exclude_if` and ad hoc validators (`resource_suspensions` normalizer models.py:513-540, `GreatPerson.deeds` normalizer :668-680, `faiths.ensure` on load). Pydantic `BaseModel` classes here set no `model_config`, so unknown keys are silently ignored (pydantic v2 default). Future migrations therefore have nothing to key off. Suggested: add an explicit version field with `exclude_if` at its default so existing bytes do not change.
6. [med] sim-depth/fragile — Fixed-width arrays encode a 3-slot limit into the schema: `resource_types`, `resource_base_yields`, `resource_reserves`, `resource_effective_yields`, `resource_current_yields`, `fishery_stocks`, `fishery_yield_ratios`, `fishery_catch_budgets` all hard-code length 3 (models.py Region, ~:470-500). Changing this touches the Rust FFI and serialized bytes.
7. [med] sim-depth — Enumerations are small: `TechEra` 8 values (models.py:63-71), `Resource` (specialized) 6 (:74-81), `Disposition` 5, `ActionType` ~35, `ResourceType` 8 mechanical classes with 255 as the empty sentinel (:83-93). `MAX_CIV_RECORDS = 254` (ffi_constants.py:79, civ ids are uint8), `MAX_FAITHS = 16` (religion.py:54), max 32 rivers (scenario.py:483), region carrying capacity clamped 12-80 (geography.py:381-382).
8. [med] sim-depth — World generation is thin. Template worlds have 12 hand-written regions (world_gen.py:29-40), 6 civ templates (:44-49), 10 leader names (`LEADER_NAMES` :51) and 10 titles, and 10 `ALL_TRAITS` (leaders.py:123-126). `LEADER_POOL_SIZE = 24` (world_gen.py:278). Terrain-to-resource mapping is one label per terrain (`TERRAIN_LEGACY_RESOURCES`, geography.py:106-111), so there is no per-region endowment variety beyond the terrain choice and no ocean, lake, island, volcano or karst type.
9. [med] docs — Scenarios: all 6 YAMLs use only keys that `ScenarioConfig` accepts (checked with `ScenarioConfig.model_fields`). `fantasy_default.yaml` has only `name`, `description`, `world_name`, so it is effectively a no-op. `secession_pool` is read by nothing (see the streamlining table).
10. [low] dead-code — `Relationship.grievances` (models.py:637-638) is documented as "never written by the simulation". Searched `src/` for `.grievances` and `grievances=`: no writer and no reader in Python. Only `tests/conftest.py:114,121` writes it, `tests/test_models.py:48` reads it, and `viewer/src/types.ts:139` declares it.
11. [low] dead-code — `Event.consequences` (models.py:738-739) is documented as "never written by the simulation". `consequences=` on `Event` has no writer in `src/`.
12. [low] bug (inconsistent) — `Civilization` (models.py:567-569) says "Do not add ge=/le= kwargs — they are silently ignored", but several model fields elsewhere use `Field(ge=..., le=...)` (e.g. `household_mobility_liquid_requirement` :1197). Either the convention or the comment is stale; it is a trap for anyone adding bounds.
13. [low] fragile — Transient fields are split across `exclude=True`, `PrivateAttr` and plain fields (e.g. `Civilization.regions_start_of_turn` models.py:~596, `WorldState.pending_shocks` :1260). The rule that transient signals are cleared before return is enforced only by convention.
14. [low] perf/complexity — `WorldState.region_map`/`civ_map` caches (models.py:~1310-1325) are invalidated manually through `invalidate_*` calls; there is no enforcement that structural edits call them.

**Simulation depth**
- Add terrain and resource variety in the template path too: template regions use only 6 terrains and 5 resource labels; procedural geography already has 10 terrains, so the template generator could draw from them.
- Widen the fixed 3-slot per-region resource arrays (and the matching fishery arrays) to a configurable slot count; this is the main structural limit on resource diversity.
- Expand the civ and leader pools (6 civ templates, 10 names, 10 traits): generated civs currently come from a small hand-written pool, which limits a broad grand world.
- Make scenario `starting_conditions` and `event_probability_overrides` the main levers for a "grand" world and document them, since only `post_collapse_minnesota` uses starting conditions.
- Add a settlement-count or city-size tier driven by carrying capacity (currently clamped to 12-80 in procedural geography).

**Confidence**
Verified by direct read and grep: field counts (AST), tuning-key reader absence (K_ names and literal strings in `src/` and `chronicler-agents/src/`), scenario key validity (ScenarioConfig.model_fields), `ecology.py` lacking `hills`, `m53a_frozen.yaml` crash path, `secession_pool` readers. Partial: a full cross-repo usage count over all ~200 model fields was started and stopped because it ran too long on the shared CPU, so the per-field "never read" list is limited to the ~20 spot-checked fields; the rest is unverified. Lines saved in the streamlining table are estimates.
