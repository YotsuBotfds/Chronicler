## 1. Goal and scope
Fix nine audited defects without changing the outcome of any accepted, valid run. Each change either refuses a bad input earlier, removes a latent hazard, or tidies repository files. Out of scope: FIX-8 (viewer), the merge of `LiveView.turns` with `LiveServer._init_data` (needs a `LIVE_VIEW_VERSION` migration), the model-id defaults in `llm.py`, and every RNG, seed or economy correction (COR-*, DEP-6).

## 3. Design
- **FIX-1.** Catch `(TypeError, ValueError, OverflowError)` at `live.py:1132`. Before `stat` and `civ_name` are used as set members, require `isinstance(..., str)` and answer with the existing "Invalid stat" error (FIX-11). Extract the coercion into `_coerce_set_value(value) -> int | None` so a unit test can reach it without a thread.
- **FIX-2.** No change to `food_accounting.py`. Add a test that a capture leaves `after_open - opening` untouched and `balance_residual` at 0 with `captured > 0`, and write that conclusion in the CONTINUATION note so the claim is not re-raised.
- **FIX-3.** Add `clear_region_transients(world)` to `utils.py`: deletes `_culture_investment_active` when present; sets `schism_convert_from/to = 0xFF`; sets the three M48 flags and `_raided_this_turn` to False; `_catastrophe_deaths_this_turn` to 0. In `agent_bridge.py:547-571` read all locals first, then call it once (the clears and reads touch different attributes, so order is equivalent). In `simulation.py:2379-2387` replace the inline loop with the call. Off-mode outcomes are identical because no reader exists in that mode. The only visible change: pickled off-mode checkpoints hold counter 0 and a False flag where they held a growing count.
- **FIX-4.** `git mv` `m53_baseline.yaml`, `m53_pass1_all.yaml`, `m53a_frozen.yaml` to `docs/validation/m53/`; leave `codex_m53_secession_threshold25.yaml`. Point `scripts/m53_baseline.py:141` and `README.md:261` at the new places. Add a test that every `tuning/*.yaml` loads with `warnings` as errors. The loader-side `kind: record` refusal is dropped: `tuning.py` is pinned.
- **FIX-5.** In `historiography.save_sidecar` and `languages.save_sidecar`, replace both write branches with `atomic_write_text(path, text)` (`artifact_io.py:156`). Keep the `atomic` parameter accepted and ignored so no caller changes.
- **FIX-6.** (a) `settle_food_purchases`: replace `assert!` with `return Err("a food purchase above its payers' cash")`; replace `panic!` with `return Err("a food sale by no living seller")`; add `if money.paid > 0 && weights all <= 0 { return Err("a food purchase with no sale") }`. Convert the two `should_panic` tests to `is_err()` plus an unchanged-pool assertion. (b) Comparators: `total_cmp` alone is wrong, because `-0.0.total_cmp(&0.0)` is `Less` while `partial_cmp` says `Equal`, and the current code then falls through to the tie-break key. Use `(a + 0.0).total_cmp(&(b + 0.0))` (adding `+0.0` turns `-0.0` into `+0.0`) via a private `fn cmp_f64` in each file (no shared module: `lib.rs` is pinned). For finite inputs the order is unchanged; NaN now has a fixed place instead of a panic or an inconsistent sort. `formation.rs:1029` (`PairKey::before`) stays: its comment says it only sees finite scores.
- **FIX-7.** (1) Replace each `values[x] is True` gate with `_on(world, values, x)`; when the switch is only saved, append `; this world has it on: pass --no-<x> to end it` and raise `LivelihoodsRefusal`, as the existing `timber_supply` and `household_retail` branches do. The explicit-request text stays byte-identical. (2) At the end of `_check_prerequisites` loop over all `_CHOICE_FIELDS`: a given key whose switch is not `_on` raises `--<key> requires --<switch>`; a given key that differs from the saved field raises `... conflicts with the saved world (<field>: <saved>)` (the first loop's text). Running it last keeps every message from the module checks. (3) Whether a state.json resume may deliberately change `workshop_mode` is an owner question (section 8); the default is to refuse, matching exact resume. (4) Add a differential test that, for each catalog key with `requires`, the imperative check and `feature_catalog.unmet_requirements` agree on a pass/fail matrix. Driving the CLI text from `REQUIREMENTS` is deferred to CON-1, because the messages are pinned.
- **FIX-9.** Keep the `complete()` signature. Add module constants `DEFAULT_TIMEOUT_S = 120.0`, `BATCH_DEADLINE_S = 24*3600`. Pass `timeout=` to `OpenAI`, `Anthropic` (`timeout=`, `max_retries=0`, since the local retry exists) and `genai` (`http_options`, milliseconds; unverified). Add a typed `LLMTruncated`, `LLMBudgetExceeded` (both `RuntimeError`, so the narrator fallback catches them). Anthropic: count `stop_reason == "max_tokens"` in `truncated_count`, log once, return the partial text. Gemini: same with `finish_reason`. `__init__` takes `max_total_tokens: int | None = None` and `max_calls: int | None = None`; exceeding raises `LLMBudgetExceeded` before the call. `batch_complete` takes `deadline_s` plus injectable `sleep` and `clock` for tests; on expiry it returns `[None]*n` as the expired branch does. No CLI flag (`main.py` is pinned); `create_clients` gets optional keyword parameters only. The default model ids and `test_llm.py` assertions are untouched.
- **FIX-10.** (a) `LiveServer._start_error`; `_run_loop` catches, stores and sets `ready`; `start()` raises `LiveServerStartError` when stored or when the wait times out; `run_live` prints the cause and returns. (b) `_scenario_file(name)` resolves under `Path("scenarios").resolve()` with `is_relative_to`, used at `:1308` and `:1496`; a bad value gives a lobby error. (c) Wrap the report and bundle reads in `asyncio.to_thread`, and take the `narrate_range` deep copy inside the thread. (d) The reconnect-state merge and holding `client_lock` over `send` are deferred.

## 4. Compatibility
No saved format changes. FIX-3 changes only the value of private attributes in pickled off-mode checkpoints; loaders ignore them. FIX-5 changes a write failure from `OSError` to `ArtifactIOError` (a `ValueError`). FIX-7 makes some resumes of inconsistent saved worlds fail; no valid world is affected. FIX-4 moves files out of `tuning/`; nothing in `src/` or `scripts/` reads them except `m53_baseline.py`. No flag is removed.

## 6. Classification
Behaviour-preserving: FIX-1, FIX-2 (test only), FIX-3, FIX-4, FIX-5, FIX-6 (finite inputs), FIX-9, FIX-10. FIX-7 is a CLI-acceptance change. Proof: oracle lane, `scripts/turn_speed_identity.py run/compare` before and after, native tests for FIX-6. FIX-6 and FIX-3 touch default-path code, so run the 9 identity cases and a 20-seed hybrid digest compare on `main` against the branch; the 200-seed gate is not required because no outcome is meant to change, and the plan must say it was not run.

## 7. Tests
`test_live.py`: inf, nan, `1e999`, list `stat`. `test_food_accounting.py`: capture residual. `test_agent_bridge.py`, `test_agents_off_determinism.py`: multi-turn reset of both fields in off mode and across 3 hybrid builds. `test_historiography.py`: no `.tmp` left after a forced failure. `test_tuning.py`: all `tuning/*.yaml` load clean. `test_livelihoods_wiring.py`: orphan, saved prerequisite, saved conflict, differential. `test_llm.py`: fakes for timeouts, truncation, budget, deadline. Rust: `wealth_transfer.rs` tests above, a comparator test with `-0.0`, `0.0` and NaN keys per file.

## 8. Risks and open questions
Tightening FIX-7(1) may fail existing tests that resume off-mode saved worlds with workshops on; list and review each. Owner decision: may a resume change a saved mode? FIX-6 zero-weight: Err versus refund-all (reachability was not proven; `provisioning.rs:923` only lists sellers with `sold > 0`, so it looks unreachable). Rollback: each PR reverts cleanly; no data migration.
