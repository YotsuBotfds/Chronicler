# Satisfaction-to-decision region partition reuse

This source candidate starts from qualified-CI `535b3b6c0f5afb5d89925a4b35e8a0e6227f19ab`. It returns the owned region partition already constructed by private `update_satisfaction` and retains it for the later decision loop. The update still partitions at its original boundary after merchant mobility, movements and merchant returns. Its satisfaction arithmetic, parallel collection, sequential writes and relief order remain unchanged.

Between satisfaction and decisions, the tick only appends memory intents from current fields, computes region statistics through `&AgentPool`, and constructs the existing pre-decision ID lookup through `&self`. These operations change neither live membership nor region assignments. Each region bucket and ascending slot order therefore match the removed decision-phase partition. Both observed and ordinary decisions retain their existing consumers, draws and region order. The private function has one production caller and two existing direct test callers; the latter continue to discard the returned value at their semicolons. Public APIs, persistence/schema and the fresh post-migration/demographic partitions are unchanged.

The structural saving is one capacity scan, one outer vector with region buckets, and another set of live slot indices in valid regions per tick. The existing satisfaction partition now stays live through memory-intent generation, region statistics and the pre-decision lookup. That extended lifetime can overlap other allocations; this source change establishes no unconditional peak-RSS or speed improvement.

One authored native boundary regression consumes the returned groups through the real observed decision evaluator after statistics and lookup construction. It covers an empty pool, empty regions, a dead slot, a genuinely killed/spawned reused slot, changed current regions and a travelling merchant whose satisfaction is preserved despite relief. It checks observed stable IDs/regions, trip exclusion from evaluated utilities and unchanged read-only decision state. It is not a copied full-tick reference or an old/new whole-world proof.
