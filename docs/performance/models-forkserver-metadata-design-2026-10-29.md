# Current-source metadata qualification design, 2026-10-29

Status: **inactive design; no metadata forks have run**. This follows the
[inert stage-1 contracts](models-forkserver-contracts-2026-10-29.md). The
separate design branch is `lead/models-forkserver-metadata-design-20261029`;
the stage-1 branch remains at `9848e7daa93d075f05a01201aba85233f5baf540`.
No controller/preload runtime is implemented or exposed by this deliverable.

The fixed proposed exposure is two real server forks, zero worlds, zero
simulation ticks, zero checkpoint reads/restores and zero native builds or
runtime imports. It tests whether the new producer can form a pristine,
models-only fork template. It cannot establish full-state continuation,
scientific outcomes or speed. The source-reviewed design and final executable
controls need a frozen registration and root review before either fork runs.

## Dedicated controller and exact preload prefix

Launch a fresh, stdlib-only controller script as its own session, outside
the gate API caller. Its imports may include multiprocessing/process and
source-verification helpers; they must not include Chronicler, NumPy,
Pydantic, PyArrow or the native extension. Freeze its exact executable,
flags, dependency files, environment and source path before launch.

The controller calls `set_forkserver_preload(["metadata_preload"])`; it
must replace the default list rather than preload the caller's `__main__`.
`metadata_preload` first installs source/import/object/thread guards and
then imports this exact ordered prefix:

1. `chronicler`
2. `numpy`
3. `numpy.random`
4. `pydantic`
5. `chronicler.models`

Its own helper imports remain stdlib-only. Actual Chronicler modules must
match the registered 25-module source set, file paths and content hashes.
Record the entire actual imported-module inventory and dependency file hashes;
the static list does not preapprove unexpected imports. Check each prefix
step and freeze the model/template fingerprint only after the final step.
Two consecutive initial fingerprint reads must agree and preserve both RNGs;
this is a fixed observer-neutrality check, not an adaptive cache-warming loop.

Before every actual `os.fork` in the server require one OS task, no forbidden
module family (`chronicler.main`, `pyarrow`, `chronicler_agents`), no WorldState
or native simulator instance, the exact actual module set, unchanged model/
class metadata, private marker and Python/NumPy global RNG bytes. Import hooks
must reject attempted forbidden imports, even if an exception is caught.
Use the previously reviewed type-safe GC classifier, with exact provenance;
do not access arbitrary object descriptors. Imported immutable data records
are permitted; constructing a world or native runtime is not.

The guard wraps the actual server `os.fork` and records a monotonically
increasing sequence. This registration admits exactly two such forks. A
generic future server also has a hard ceiling of eight sequential jobs, with
a new server/tracker after that; this two-child exercise does not qualify
eight-child lifetime, parallel children or world execution. Count actual
fork and wait4 rows, not merely submitted Process objects.

## Ownership before child bootstrap work

The old target-function handshake occurred after multiprocessing bootstrap.
For this stronger design, the child branch of the server fork wrapper calls
`setsid()` before returning to the forkserver bootstrap. It then sends only
a bounded primitive PID/birth/session record over a private controller-owned
Unix socket, and waits for acknowledgement. This happens before target-module
unpickling/import, metadata reads or mutations. The already loaded server
template is inherited; this is not a claim that it was absent before ownership.

The controller accepts only its expected fork PID with matching SO_PEERCRED,
opens a pidfd, checks `/proc` creation ticks/session/group again, and acknowledges
only the same birth identity. The private socket directory is mode 0700;
messages are capped at 4 KiB and the ownership handshake at two seconds. No
path supplied by an untrusted child chooses a destination or signal target.
Bootstrap may proceed only after this acknowledgement. If identity is unknown,
stop and retain an unqualified result; never signal a guessed or recycled PID.

No child descendant creation is admitted in this metadata exercise; reject
extra processes in the observed topology and forbid launch calls in the
reviewed metadata-only child path. The controller
pins the forkserver/tracker as its own direct children and holds ownership
through cleanup. The server's wait4 wrapper reaps its metadata children;
the controller verifies the exact two reap records and reaps its own direct
server/tracker children. It verifies all owned
sessions/groups are empty. Cancellation, signal, timeout, guard refusal or
uncertain cleanup makes the whole proof fail with no fallback or retry.
Real tiny POSIX tests must verify the new pre-bootstrap handshake and failure
cleanup before the registered metadata exercise; pure mocks are insufficient.

The first child's concrete mutation list is frozen before execution:
`scientific_research_state.MAX_CYCLES`, a private attribute on
`LazyResearchModel`, `ScholarshipState.model_config`, the scholarship
`COUNTER_KEYS` binding, `ScientificClaimsState.lazy_name`, the
`ScientificClaimsState.model_fields` mapping and epidemiology's
`PATHOGEN_INDEX` mapping. Use disjoint private sentinel keys; never construct
or activate research state. The witness must distinguish changes to both
bindings and nested mutable contents. These mutations are child-private
isolation probes, not simulation parameter changes.

Python's standard random singleton receives automatic at-fork entropy in a
child. Record its child hash descriptively; do not require it to equal the
server or the other child. Require the **server's** Python RNG to remain
unchanged immediately before each fork. NumPy's inherited singleton state
must match the frozen server before either child mutates it. No checkpoint
global-RNG restoration is being claimed.

Require exact sets and order for two pre-fork guard records, actual fork
records, acknowledged births, child receipts and successful wait4 reaps.
Record each child's user/system CPU from the server's wait4 wrapper. All
final source/environment identities and imported module sets must match;
all completed and failed records remain retained. Extra, missing, unknown,
duplicate or incomplete records cannot qualify a proof.

## Resource registration and publication boundary

The companion design JSON fixes proposed exposure and limits. It remains
nonexecutable until controller/preload/codec implementations, pure/POSIX
qualification, exact source/environment pins and root review are recorded.
Do not auto-fill a missing pin at execution time.

Proposed limits are one CPU, 30 aggregate CPU seconds, 45 aggregate wall
seconds, five CPU/eight wall seconds per child, and at most 32 MiB of evidence.
Reserve both complete child allowances before starting. Require at least
3 GiB disk plus 64 MiB evidence/scratch reserve and 1 GiB available memory
at admission; keep 3 GiB/512 MiB floors during execution. Timeouts include
startup, ownership, guards, receipts, cleanup and final serialization/hashing.
Keep stdout/stderr and JSONL rows bounded; reserve encoded bytes before writes.

Use an external stdlib supervisor to retain authoritative controller exit,
resource/cleanup observations and final producer receipts. During execution it
accounts for the complete owned tree and reaped usage, without counting the
same descendant once in a wait4 row and again in its reaped helper's total.
A leader-only RLIMIT is not an aggregate CPU cap. Final accounting is checked
after helpers exit. The implementation must qualify live accounting and
expiry during final serialization/hash/publication with injected failures.

Controller output is a candidate result until that terminal supervisor check.
An independent reader may publish qualification only after exit zero, exact
closed record coverage, complete owned cleanup, unchanged input hashes and
all budgets are verified. Its own bounded readout work has a separately
registered budget; it cannot silently move producer finalization outside the
producer budget. Root must review this concrete authority boundary with the
implementation before activation. No positive result exists in this design.
